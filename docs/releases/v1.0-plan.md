# v1.0 实施计划与 v2.0 演进边界（Phase A）

## 1. v1.0 完成定义

在干净环境下安装包，通过标准 CLI 使用**有版本的合成日频股票数据**执行一条包含数据、金融计算、研究、基准预测、策略、组合、风控、模拟成交和绩效报告的纵向工作流，输出可审计的 run-manifest、成交账本和净值曲线。所有核心数学和时间语义测试通过。v1.0 不承诺盈利，也不提供真实下单功能。

参考研究配置：三只合成股票、约 80 个以上交易日（满足动量预热及后续成交）、20 交易日动量、月度调仓、按分数排序最多选 2 只并尽量等权、单资产目标权重 <= 50%、总仓位 <= 100%、现金 >= 0；收盘信号，下一有效交易日开盘成交；手续费和滑点均为显式参数。因子不等于预测：初期允许采用已明示的确定性线性基准打分模型，训练与测试区间不能重叠。

v1.0 真实数据适配器可以列为非阻塞实验项，不能拿无许可数据作为默认发布依赖。

## 2. 任务包（一个模块至少代码+文档+测试+示例）

| Work item | 最小可交付代码能力 | 独立验证 |
| --- | --- | --- |
| M00 core | 时间、货币、订单与结果值对象；数据 schema | 类型与 invariant 测试 |
| M01 data | 生成/加载 fixture、校验、历史 as-of snapshot、交易日历 | 缺失/未来数据/重复数据负向测试 |
| M02 finance | 收益、波动率、协方差、NAV 和基础风险指标 | 独立 hand-calculated golden cases |
| M03 research | 20 日动量因子、截面排名、简单 IC 报告 | 人工排序与标签时间窗口 |
| M04 models | 可复现的简单基准预测接口，记录 cutoff | 时间切割、参数隔离、确定性测试 |
| M05 strategies | 排序与月度调仓的信号规则 | 同输入同信号、缺失处理 |
| M06 portfolio | 最多 2 标的等权、现金和目标权重限制 | 权重 <= 1、无负权重、边界测试 |
| M07 risk | 目标与拟议订单的现金、仓位、时间、价格检查 | 明确拒绝码、绕过风险门禁失败 |
| M08 execution/evaluation | 下一开盘模拟、费用/滑点、现金仓位账本、报表 | 黄金账本案例、净值守恒、成本单调性 |

各模块共享的公开 DTO 由 Core 维护；模块 PR 不能私自改变核心时间或货币语义。

## 3. 实施阶段

**Phase A — 架构基线（本 PR）**
- 建立架构、契约、数据时间语义、ADR。
- 建立数据证据链、Git 治理、版本范围、验收规范。
- 只接受文档验收，不声称能跑回测。

**Phase B — 可安装工程基座**
- 创建 `pyproject.toml`、`src/nano_quant`、基础 API、配置 schema、合成数据生成脚本、`pytest`、lint/typing 和 GitHub Actions。
- 标准可执行命令（拟议，实施时最终固定）：
  - `python -m pip install -e ".[dev]"`
  - `python -m pytest -q`
  - `python -m nano_quant.cli backtest --config examples/daily_equity_v1.yaml`
- 通过 smoke test 验证正确安装；可暂用 stub，但必须显式标明尚未实现。

**Phase C — v1.0 纵向实现**
- 先用一个信号和一次买入的最小用例打通 Data→Report，再补全月度多资产策略。
- 分模块创建 PR，避免一次合入无法审查的大改动。
- 维护 `docs/modules/` 的实际 API 使用与限制文档。

**Phase D — 独立验证**
- 先实现 `../validation/acceptance.md` 中最关键的时序/账本/风险 golden tests。
- 再做集成、时间反事实、重复运行和依赖环境重建。
- 演示完成前，任何样本内表现只是调试证据。

**Phase E — 发布**
- CI 必需检查全部通过，提交 v1.0 release notes、数据/环境/代码版本；从稳定化分支与 main 一致的实际发行提交创建 `v1.0.0` 标签。

## 4. v1.0 明确不做

- 真实券商交易 / 账户授权 / 自动真实下单
- 高频 / 盘口微结构 / 分布式交易集群
- 空头、融资杠杆、复杂衍生品结算
- 用高级机器学习替代所有可解释基准
- 声称使用合成数据证明真实 Alpha
- 未获数据许可的自动爬取或二次分发

## 5. v2.0 价值驱动的候选能力

在 v1.0 运行证据出现后优先考虑：多因子、Walk-forward 与 purged 时间验证（标签重叠时）、回归/树模型比较、组合约束优化、更完整的因子与风险归因、成本/容量敏感性、实验注册。每个能力需要独立问题陈述、对照基准和非回归测试，不为版本数字增加功能。

## 6. 从 v1.0 到 v2.0 的兼容性

- 保护公开 core DTO 和 CLI 的语义；新增字段先采用向后兼容的缺省与迁移策略。
- 数据 manifest / 回测账本 schema 增加版本标识，保留旧版读取或提供显式迁移。
- 确保 v1.0 golden tests 在后续分支继续通过。
- 不兼容的时间或会计语义必须新建 ADR，并以 MAJOR 版本发布或明确兼容适配层。
